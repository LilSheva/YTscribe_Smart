# 🏗 Архитектура YTS_bot

В данном документе описывается высокоуровневая архитектура, взаимодействие компонентов и потоки данных (Data Flows) в проекте YTS_bot.

## 1. Общая парадигма (Local-First + Cloud AI)
Бот физически работает на локальном ПК пользователя (хост-машина). Это решает проблему хранения объемных медиафайлов и авторизации через локальные браузерные куки. Тяжелые вычислительные задачи (Транскрибация и LLM-аналитика) делегируются внешним облачным API для максимальной скорости и экономии ресурсов хоста.

### Ключевые архитектурные паттерны:
- **Асинхронное ядро:** Телеграм-бот крутится на `asyncio` (`aiogram 3.x`).
- **Изоляция блокирующих вызовов:** Все операции с диском, вызовы `yt-dlp` и `ffmpeg` оборачиваются в `asyncio.to_thread()`, чтобы не стопить прием новых сообщений.
- **Feature Toggles:** Модульная система. Каждый сервис включается/отключается флагом из конфигурации.

---

## 2. Структура слоев (Layers)

1. **Telegram UI Layer (`bot/`)**
   - Точка входа для взаимодействия. Принимает ссылки и промпты.
   - Рендерит кнопки в зависимости от активных Feature Toggles (если `ENABLE_TRANSCRIPT=False`, кнопка генерации текста не показывается).
2. **Business Logic Layer (`services/`)**
   - Набор независимых сервисов, которые не знают о существовании Telegram. Принимают данные, возвращают результат или выбрасывают кастомную ошибку.
3. **Storage & DB Layer (`services/knowledge_base.py`, `services/gdrive.py`)**
   - Работа с файловой системой (папка `temp/`), подключенным Google Drive API и векторной базой данных ChromaDB.

---

## 3. Потоки данных (Data Flows)

### Pipeline A: Парсинг и формирование UI
1. Пользователь отправляет сообщение: `https://youtu.be/... [опциональный промпт]`.
2. Бот перехватывает URL и сохраняет промпт в состояние `FSM` (или передает в callback_data).
3. `services.downloader.get_info(url)` выполняется в отдельном потоке. Скачиваются только метаданные (Title, Channel, Duration).
4. Бот генерирует приветственное сообщение и инлайн-клавиатуру, проверяя `config`.

### Pipeline B: Базовое скачивание (Медиа)
1. Нажатие "Скачать M4A/MP4".
2. Вызов `services.downloader.download_media(url, format_type)`.
3. Файл сохраняется в локальную папку `temp/`.
4. Бот отправляет файл пользователю в Telegram (если размер <= 50МБ).
5. (Опционально) Если файл > 50МБ или активен `ENABLE_GDRIVE`, файл пушится на Google Drive, а юзеру отправляется публичная ссылка.
6. Файл удаляется из `temp/` (сборщик мусора / cleanup).

### Pipeline C: Умная аналитика (Smart Processing)
Самый сложный пайплайн, активируется нажатием "Выжать суть (Чат) / Создать .MD".
1. **Скачивание:** Бот скачивает аудиодорожку (M4A) во временную папку.
2. **Анализ размера:**
   - Если M4A < 25MB: Файл идет напрямую в Groq Whisper API.
   - Если M4A > 25MB: Вызывается хелпер `utils.media_chunker`, который через `ffmpeg` режет аудио на сегменты по ~20МБ.
3. **Транскрибация (`services.transcriber`):**
   - Чанки асинхронно отправляются в Groq API. Текст склеивается.
4. **LLM Обработка (`services.llm_router`):**
   - Склеенный текст + "промпт пользователя" упаковываются в запрос и отправляются в Kiro AI / Omniroute (модель выбирается из настроек, например Claude 3.5).
5. **Экспорт:**
   - Ответ выдается в чат (разбитый на сообщения по 4096 символов, если нужно).
   - Либо формируется и отправляется красивый Markdown-документ.
6. **Сохранение в память:**
   - Транскрипт передается в Pipeline D (База знаний).

### Pipeline D: Векторная база знаний (ChromaDB)
1. Получен сырой текст из Pipeline C.
2. Текст разбивается на смысловые фрагменты (chunks) с небольшим перекрытием (overlap) в `utils.text_chunker`.
3. Фрагменты векторизуются (через встроенные модели эмбеддингов ChromaDB или внешний API) и сохраняются в локальную базу данных, физически расположенную в синхронизируемой папке Google Drive.
4. При запросе пользователя (команда `/search <текст>`) бот ищет релевантные куски в ChromaDB и передает их в LLM для формирования ответа.

## 4. Управление ошибками (Error Handling & Graceful Degradation)
Ввиду модульности, падение одного сервиса обрабатывается локально:
- Ошибка `Groq API timeout` -> пользователю возвращается уведомление "API транскрибации временно недоступно", при этом скачивание M4A продолжает работать.
- Ошибка `yt-dlp (bot detection)` -> бот пробует переключить user-agent или использовать куки браузера (Fallback-стратегия).
- Забыта очистка папки `temp/` -> при каждом старте бота срабатывает скрипт `startup_cleanup`, удаляющий старые медиафайлы.
